# 微信聊天记录导出 · 本机修复版

基于 [qwe11223/wechat-exporter-mac](https://github.com/qwe11223/wechat-exporter-mac) 的现有本地版本修复，并引入 [macos-wechat-export](https://github.com/DaneelOlivaw1/macos-wechat-export) 的临时微信副本配置流程。

## 第一次使用

1. 在「系统设置 → 隐私与安全 → 完全磁盘访问权限」允许「终端」。授权后按系统提示重开终端。
2. 用官方微信登录本次账号，确认需要导出的记录已经在这台 Mac 上。只处理账号本人授权的数据。
3. 双击 **开始.command**。按显示的编号选择本次账号。
4. 保存微信草稿，从微信菜单正常退出；在终端输入 **YES**。临时微信窗口出现后，由账号本人完成手机确认或扫码登录。
5. 等待配置结束，工具会尝试恢复官方微信，并打开本地导出界面。登录与配置默认最多等待 15 分钟，超时会关闭临时副本；再次运行会发起新的手机登录请求。
6. 在界面点选账号、联系人、日期与格式，先预览再导出。文件存到本机 `~/Library/Application Support/WeChatExporterLocal/exports/`，界面也提供下载链接。

已配置的账号以后双击 **启动.command** 即可。要增加账号或重新捕获密钥，双击 **配置账号.command**。不同账号必须分别由本人登录授权和配置，不存在一次签名就能读取任何人记录的功能。

## 已修复

- 截断、无法执行的启动脚本。
- 网页打开端口和实际服务端口不一致。
- 每个账号独立保存经过验证的密钥；界面不会自动读取第一个账号。
- 缺少账号配置时给出提示，不在网页后台自动扫描微信进程。
- 导出时复制数据库及 WAL 后处理，保留尚未合并进主数据库的新消息。
- 有数据库解密失败时停止，避免无提示地导出不完整记录。
- 关闭 Flask 调试模式，仅监听本机 127.0.0.1。

## 当前验证状态

已通过人工生成的 v3/v4 数据库导出测试，以及账号隔离、密钥权限、WAL 消息和缺失密钥测试。已验证图形界面可以启动。

本机实测环境为 Apple 芯片、macOS 27.0.1、微信 4.1.15。当前账号已成功捕获并校验 24 个数据库密钥。通过与网页相同的导出接口，成功解密 7 个必需数据库，并将文件传输助手的一天内 5 条真实记录导出为 TXT、CSV、HTML；CSV 行数和 TXT 消息总数与数据库计数一致，HTML 包含本机已有的图片。测试内容与密钥仅保存在本机，未进入源码或 GitHub。

早期副本启动失败由系统保留的旧签名授权导致。移除失效的 WeChat-trial 权限记录，再从准确路径重新添加同一份副本后，副本成功运行。配置完成后已关闭临时副本、恢复官方微信，并撤销副本的完全磁盘访问权限与 ChatGPT 的微信数据访问；原版微信签名未改变。

其他账号仍需分别由账号本人登录授权后配置。不能保证所有系统和微信版本都兼容；图片、语音和视频需要媒体文件已在本机，语音转文字等可选依赖尚未验证。修复版仓库为 [htcdesirezjohnson/wechat-exporter-mac](https://github.com/htcdesirezjohnson/wechat-exporter-mac)。本地也保留源码 Git 提交和 ZIP 备份。

## 本地数据和仓库

- `~/Library/Application Support/WeChatExporterLocal/` 保存账号密钥、日志和解密副本，位于代码仓库之外。
- 上述应用数据目录下的 `exports/` 保存导出内容，避开文稿/桌面的 iCloud 同步目录。
- GitHub 只保存程序、文档和人工测试，不上传微信数据库、密钥或聊天。
- 配置阶段只为临时微信副本签名。原版微信程序和 SIP 设置保持原状；副本登录仍属于真实登录，会访问该账号的本机数据。
- 不需要全程 sudo，不需要付费 Apple 开发者证书。

## 排错

- “Operation not permitted / 无权读取微信目录”：确认终端的完全磁盘访问权限已开，并从终端运行本工具。其他应用启动的子进程不会继承终端的授权。
- macOS 27 中副本立即退出（退出码 255、捕获数量为 0）：先检查系统日志是否报告微信数据目录 `Operation not permitted`。如果是，在「系统设置 → 隐私与安全 → 文件与文件夹 → 微信」检查其下的「微信」数据访问开关。该权限与终端权限不同，须由用户明确同意后开启，再重新配置；不要只因看到原版微信恢复的登录窗口就认为配置成功。Apple 对默认拒绝跨开发者应用数据访问的说明：https://developer.apple.com/documentation/macos-release-notes/macos-27-release-notes#System-Integrity-Protection
- 如果上述开关被再次重置且系统日志报告签名匹配失败，不要反复重跑。可先准备并校验一份固定的临时副本，使用 `--prepared-copy` 指定它；本机 `prepared-copy-path.txt` 仅记录该临时路径，`开始.command` 会在路径仍有效时复用。如果系统仍使用旧签名，先在系统设置移除失效的 WeChat-trial 条目，再从准确路径重新添加同一份副本。仅切换开关可能仍沿用旧签名。是否授予副本完全磁盘访问权限由用户决定；测试结束后撤销临时授权。工具不会自行修改系统权限数据库。
- “先退出微信”：保存草稿，使用微信菜单退出，再重新配置。
- 配置期间没有捕获到密钥：确认登录的是菜单里选择的账号，可在临时微信里点开需要导出的聊天；不要关闭 SIP 或修改官方微信来碰运气。
- “部分数据库未能解密”：重新配置该账号。旧的配置不会因失败被覆盖。
- 基础依赖缺失：双击 **安装依赖.command**。本机已检测到可复用的 Python 环境，无需先重复安装。

本机日志位于 `~/Library/Application Support/WeChatExporterLocal/setup-status.log` 与同目录的 `app-status.log`；日志不输出密钥。请勿公开上传本地数据目录。
